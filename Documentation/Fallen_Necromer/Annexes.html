Comment lire les sources

Cette annexe complète les trois guides. L’audit des assets a été effectué dans l’éditeur du projet ; les fichiers de code cités sont ceux du plugin actif. Une propriété de classe est une valeur par défaut : une instance placée ou un événement de démarrage peut la remplacer.

Les catalogues ne sont pas une preuve que chaque fichier est utilisé. Les dossiers Archives, les anciens montages Jaune/Rose/Simple et les sources de retarget peuvent être conservés sans participer au combo actuel. Les fonctions du réseau et du solo ont des points d’entrée distincts.

Le scénario de crash interrompt un processus d’éditeur de test puis recharge les données dans un nouveau processus. Le contrôle final confirme que le module déployé et le sous-système de reprise sont chargés dans le projet principal.

Les logs de démarrage contiennent aussi des messages d’outils optionnels absents (profilage/SDK de plateformes non utilisées). Le résultat annoncé ici porte sur les tests nommés et les assertions, pas sur une promesse de log entièrement vide.

Maintenance de cette documentation

  1. Modifier le comportement ou le réglage dans la source active.
  2. Vérifier la valeur effective en jeu, pas seulement le défaut natif.
  3. Rejouer les scénarios concernés, en solo et depuis un invité si le comportement est partagé.
  4. Mettre à jour le guide concerné, ses limites et le tableau de paramètres.
  5. Conserver les rapports de tests datés. Ne pas remplacer une preuve par une simple capture visuelle.
  6. Pour un changement de format de sauvegarde, de nom d’acteur ou de protocole, documenter la compatibilité avec les anciennes parties.

Éviter de transformer le nombre de contrôles réussis en garantie de « zéro bug ». Les essais couvrent les scénarios décrits, avec des limites explicites. Les prochaines validations prioritaires sont le vrai trajet Steam entre deux machines, la parité d’inventaire/ressources et les cas de migration de sauvegarde lors de futures modifications de maps.

Document établi à partir du code, des assets et des essais locaux du projet. Les valeurs d’asset, de classe et d’instance sont distinguées lorsqu’elles diffèrent. Les évolutions ultérieures nécessitent une mise à jour de cette documentation.
